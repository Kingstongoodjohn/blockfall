# 0002 — Synthesised sound effects, played with runtime-loaded XAudio2

**Status:** Accepted (2026-10-18)

## Context
The game had no sound. Options were XAudio2 with generated sounds, XAudio2 with `.wav` files,
or `PlaySound` (winmm). The project avoids new dependencies and large binary assets (the repo is
already ~200 MB), and game logic must stay free of Windows code so tests run without a GPU or
audio device.

## Decision
- Every sound is generated by code at startup (`src/game/sfx.cpp`: noise, tones, envelopes,
  one-pole filters). No audio files in the repo.
- Game logic only pushes `SoundEvent`s (`Game::sounds`); `src/platform/audio_xaudio2.cpp` plays
  them each frame and empties the list.
- XAudio2 is loaded at runtime (`xaudio2_9.dll`, then `xaudio2_8.dll`, system folder only) instead
  of linking `xaudio2.lib`. If it's missing or there's no audio device, the game runs silently.
- `PlaySound` was rejected: it plays one sound at a time, which doesn't work for a shooter.

## Consequences
- No new library, no binary assets, works the same with MSVC and MinGW.
- Sounds are simple and "gamey". Realistic recorded sounds would need `.wav` assets (ask first).
- Synthesis is testable: the tests check every sound is non-silent, repeatable and click-free.
- `Game::sounds` is capped at `MAX_SOUND_EVENTS` per frame, because tests run the game without
  anything draining the list.

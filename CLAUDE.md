## Overview
Blockfall is a third-person build-and-shoot battle royale prototype (Fortnite-style) written in
C++17 with Win32 and Direct3D 11, no game engine. Single-player against AI bots; party "friends"
are local accounts that play as AI teammates. There is no online server.

The player-facing feature list and controls live in `README.md`.

**Status:** v12 + battle bus deck fix. Project structure (this file, `docs/`) added 2026-10-18.
**Last updated:** 2026-10-18

## Stack
- **C++17**, built with **CMake ≥ 3.16** and **MSVC** (Visual Studio 2022 Build Tools on this PC).
  MinGW is also supported by `CMakeLists.txt`.
- **Win32 + Direct3D 11** for the window, input and renderer. HLSL shaders are embedded as strings
  in `src/platform/renderer_d3d11.cpp`.
- **Third-party (vendored single headers):** `cgltf` (glTF loader), `stb_image` (PNG). No package
  manager.
- **Tests:** a home-made `CHECK(...)` harness in `tests/tests.cpp`, no framework.
- **Asset tools:** Python scripts in `tools/` (Blender's `bpy` for the character).
- Do not introduce a game engine, a package manager (vcpkg/conan), or a test framework without
  asking. The no-engine, few-dependencies setup is the point of the project.

## How to run
CMake isn't on PATH on this PC. Use the **"x64 Native Tools Command Prompt for VS 2022"** (Start
menu), or call it directly:
`"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"`

- **Play the committed build:** `bin\Blockfall.exe` (needs `assets\` next to `bin\`).
- **Build the game:** `build.bat`, or
  `cmake -S . -B build -A x64` then `cmake --build build --config Release`
  → `build\Release\Blockfall.exe`
- **Test:** `cmake -S . -B build-tests -A x64 -DBLOCKFALL_TESTS=ON`
  then `cmake --build build-tests --config Release --target blockfall_tests`
  then `build-tests\Release\blockfall_tests.exe`. It ends with `N passed, 0 failed`; exit code 0
  means every check passed. (451 checks as of 2026-10-18, and the CPU frame-time check was ~1.9 ms.)
- **Rendering smoke test:** `Blockfall.exe --shots <folder>` plays a scripted demo and saves
  screenshots.
- **Regenerate skins:** edit `tools/character/skins_catalog.py`, then run the generator. It
  rewrites `src/game/skins_data.inc` and the textures in `assets/skins/`.

## Domain concepts
- **Modes / team size:** Solo=1, Duos=2, Trios=3, Squads=4. A match is 100 players
  (`teamCountFor()` in `game.h`).
- **Match flow:** lobby → battle bus → skydive → glide → landed (`DropPhase`). The storm shrinks
  in stages.
- **Build grid:** cell `TILE` = 6 m wide, `STORY` = 4.5 m tall (`building.h`). Pieces are Wall,
  Floor, Ramp (stairs), Cone (pyramid). Materials are Wood/Brick/Metal. Pieces need support or
  they break.
- **Editing:** walls use a 3×3 tile grid, floors/ramps/cones use 2×2. What a selected tile means
  differs by piece type (cut out, raise a cone side, stair direction).
- **Rarity:** Common → Legendary; each step adds +5% damage.
- **Knocked:** in team modes, zero HP with a teammate standing means crawling and bleeding out
  over 40 s; a teammate revives you by holding E for 5 s.
- **K-Bucks:** in-game currency, earned per elimination, spent on skins in the Item Shop.
- **Accounts:** local only, saved in `%APPDATA%\Blockfall\accounts\<name>.ini`. Settings are in
  `%APPDATA%\Blockfall\settings.ini`.
- **Bots:** play styles are fighter, hider/runner and mixed. `BOT_DAMAGE_SCALE` keeps them
  beatable.
- **Coordinates:** the game world is left-handed. `model.cpp` mirrors glTF (right-handed) into it.

## Key decisions
- **`bin/Blockfall.exe` is committed on purpose**, so the game can be downloaded and played
  without building. Don't gitignore or delete it. See `docs/decisions/0001-commit-prebuilt-exe.md`.
- **Game logic in `src/game/` has no Windows code.** That's what lets the tests run without a
  GPU. Keep platform code in `src/platform/`.
- **No engine, own renderer.** The graphics features are hand-written D3D11 approximations of
  modern techniques, not engine code.
- **The skin list has one source of truth:** `tools/character/skins_catalog.py`. `skins_data.inc`
  is generated from it, so don't hand-edit the `.inc`.
- **Game stats/tunables are named constants** at the top of headers (`game.h`, `types.h`,
  `building.h`, `loot.h`). Change numbers there, not inline.

## Hard rules
- Never push a rebuilt `bin/Blockfall.exe` unless the tests pass and the user asked for a release
  build. It's what players download.
- Never edit files in `src/third_party/`.
- Ask before adding or regenerating large binary assets (textures, `.glb`, screenshots). They live
  in git history forever.
- Ask before changing `CMakeLists.txt` or `build.bat`.

## Gotchas
- **Older README sections are stale.** The "What's in the game" section describes earlier
  versions (5 m × 4 m cells, 16 players per match, "no fall damage"). **Trust the code and the
  newest "What's new" section.** Don't change code to match old README text. Fix the README
  instead, after asking.
- **C4996 warnings (`fopen`, `strcpy`, `strncpy`) from `src/third_party/cgltf.h` are expected.**
  They're in vendored code. Ignore them, and don't "fix" them by editing cgltf. Warnings from
  `src/game/` or `src/platform/` are real and should be fixed.
- **CMake isn't on PATH.** If `cmake` isn't found, use the Native Tools prompt or the full path in
  "How to run". Don't install a second CMake.
- **The repo is ~200 MB** (binary assets in history). Every committed texture, `.exe` or
  screenshot makes it permanently bigger.
- **The tests need the working directory to be the repo root** if they load `assets/`. Run them
  from there.
